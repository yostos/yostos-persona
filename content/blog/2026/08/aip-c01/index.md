2026年8月25日に **AWS Certified Generative AI Developer - Professional (AIP-C01)** を受験し、合格ライン750点のところ、辛くも779点で合格できました。

私は元AWSコンサルタントで、学習期間は8月3日から受験日までの3週間、学習時間は準備期間を含めて体感で20時間程度でした。準備ではClaude CodeとMulmoClaudeを活用しました。

この試験は2026年3月に始まったばかりで、日本語の受験記がほとんど見当たらないと思うのでこの記事をまとめました。
受験を迷っている人が知りたいであろう、次の3点を中心にまとめました。

1. どんな試験なのか
2. 何をどれだけやれば合格ラインに届くのか
3. 教材に何が使えるのか

## AIP-C01 とはどういう試験か

正式名称はAWS Certified Generative AI Developer - Professional(以下、AIP-C01と記載)、試験コードはAIP-C01です。基盤モデル（FM: Foundation Model）をアプリケーションや業務ワークフローに組み込む能力を問う、Professionalレベルの認定です。

| 項目       |                                   内容 |
| ---------- | -------------------------------------: |
| 問題数     |     採点対象65問 ＋ 未採点10問 ＝ 75問 |
| 試験時間   |                                  180分 |
| 合格ライン |   100〜1000点のスケールドスコアで750点 |
| 出題形式   |             択一選択問題、複数選択問題 |
| 受験料     |                       44,000円（税込） |
| 提供言語   | 英語、日本語、韓国語、中国語（簡体字） |

受験料は44,000円（税込）です。AWSの受験料は認定レベルごとに決まっていて、AIP-C01はProfessionalレベルなので最も高い価格帯にあたります。
ただし、この試験を受けようと思う方は他のAWS認定を持っている方が多いと思います。
以前の受験で付与される50%の割引バウチャー特典を持っている場合があるので、
**AWS 認定アカウントの「特典」ページを必ずチェック**しましょう。

まず押さえておくべきは、**出題形式が択一選択問題と複数選択問題の2種類しかない**ことです。
択一選択問題は正解1つと誤答3つ、複数選択問題は5つ以上の選択肢から正解を2つ以上すべて選ぶ形式です。近年の他のAWS試験に見られる並べ替えやマッチングの形式はありません。解答操作そのものに慣れる必要がなく、対策は選択肢を読み比べる練習に集中できます。

次に、公式の試験ガイドで、次のものは**試験では求められない領域**として挙げられており、学習の必要はありません。

- モデルの開発と訓練
- 高度な機械学習技法
- データエンジニアリングとフィーチャーエンジニアリング

機械学習そのものの理解を問う試験ではありません。既存の基盤モデルをどう組み合わせ、どう本番環境に載せるかという開発者側の判断が問われます。

出題範囲は5つのコンテンツ分野に分かれています。

| コンテンツ分野                                    | 配点 |
| :------------------------------------------------ | ---: |
| 1. 基盤モデルの統合、データ管理、コンプライアンス |  31% |
| 2. 実装と統合                                     |  26% |
| 3. AI の安全性、セキュリティ、ガバナンス          |  20% |
| 4. GenAI アプリケーションの運用効率と最適化       |  12% |
| 5. テスト、検証、トラブルシューティング           |  11% |

出題される75問のうち10問は採点されません。
これは今後の出題候補を評価するための問題で、試験中にどれが採点対象外なのかは分かりません。採点されるのは残る65問です。

65問で750/1000点が合格ラインです。
配点は難易度の差を統計的に補正され算出されるので、「65問中これだけ正解すれば合格」という逆算はできません。

## 私のプロフィール

読者が自分との距離を測れるように、私の前提を書いておきます。

私は元AWSコンサルタントです。Associateレベルの3つの認定を持ち(内2つはExpireしています)、数年の実務経験があります。
AWSのサービス構成や、IAMやVPCといった土台の部分については、あらためて学び直す必要のない状態から始めています。

生成AI側については、Claude Codeを日常的に使っていて、Claude APIを使った小さなコードを今も書いています。APIの使い方やトークンの扱い、プロンプトの組み立てといった部分は、業務ではなく手元の道具として触ってきました。

Amazon Bedrockについては、現役時代にデモをいくつか作りました。ただし直近2年は必要性がなく、キャッチアップしていません。Bedrock Knowledge BasesやBedrock Agents、Guardrailsといった、この2年で増えた機能群は初見に近い状態でした。

つまり、AWSの土台は持っているが、AWSの生成AI周辺のサービス知識は空白という状態からのスタートです。

## 使った教材とまとめ資料づくり

最初に、 Whizlabsの「AWS Certified Generative AI Developer - Professional (AIP-C01) Certification Training」を購入しました。試験対策問題と、用意されたシナリオを実際のAWS環境で構築するLabsが含まれています。7,585円で購入しました。AIP-C01が始まった直後の2026年3月に購入しました。Whizlabsを選択したのはたまたまです。
現在はUdemyなど日本語で模擬試験を提供するサービスが多数あるので、そちらを推奨します。

ただし、買っただけで満足し4ヶ月以上放置していました。

8月に入って学習を始めて最初に手を付けたのは、公式のサンプル問題です。
試験ガイドに付属する無料のサンプル問題と、AWS Skill Builderで提供されている公式模試の両方を解きました。試験の要点はサービスの機能でなく「要件に対して最適なサービス構成を選べる」ことが問われるというのが理解できます。

次に**まとめ資料の作成**です。
Whizlabsを進めながら、引っかかった箇所をAWSの公式ドキュメントで確認し、その内容をClaude Codeに渡してAsciiDocのドキュメントに積み上げていきました。最終的に約100ページになりました。

この資料作成でほぼ知識は整理できたので、資料自体は一読して読み返していません。

## MulmoClaude に学習環境を作らせる

MulmoClaudeで自分用の模擬問題集を作りました。
[MulmoClaude](https://github.com/receptron/mulmoclaude) はあの中島聡氏が開発しているClaude Codeのマルチモーダルクライアントです。
独自の模擬問題集を作った理由は、Whizlabsが英語ベースなので日本語版が欲しかったのと、独自にまとめたナレッジも折り込みたかったからです。

Whizlabsをベースにしていますが、まとめ資料や公式ドキュメントから解説を加えています。
設問は本番と同じシナリオ形式にして、選択肢もすべて技術的には成立するものを並べる形にしました。

回答するごとに、その正誤を履歴を記録しています。

更にMulmoClaude上で進捗ダッシュボードを用意して、ドメイン別の進捗と、概念別にどこで落としているかを見えるようにしました。

「直近2回連続で正解したら習得」としました。初見の設問に対する最初の解答は、当てずっぽうで当たっている可能性が排除できないからです。この定義にすると、まぐれ当たりの問題が習得済みに紛れ込まなくなり、繰り返すべき問題だけが残ります。
間違えた問題を中心に5周ほど回しました。

私の場合、MulmoClaudeで環境を作ること自体が学習のモチベーションになりました。ただし効率で言えば、既存の模擬試験を買ったほうがよいと思います。回答履歴の管理や弱点対応、メモの書き込み、AIによるその場での質疑応答などは、多くのサービスですでに備えています。

詰め方としては、弱点である問題に絞っていくアプローチが効きました。周回を重ねるほど残る問題が減り、後半ほど1周が短くなります。進んでいる実感が出るので、最後まで続けられました。

## AIP-C01の選択肢には癖がある

学習する中で気付いた選択肢の癖をまとめておきます。誤答を消去していく手がかりとして個人的には役立ちました。

<!-- textlint-disable -->

{% admonition(type="warning", title="本番の出題傾向ではありません") %}
私が公式模試やWhizlabsから学習する中で気付いた傾向であって、本番の出題傾向ではありません。
{% end %}

<!-- textlint-enable -->

- リトライやスロットリング対策の文脈で「指数バックオフ（exponential backoff）」を含む選択肢が出てきたら、正解である確率が高い。AWSが公式に推奨するリトライ戦略であり、対比として置かれる固定間隔リトライや無制限リトライは設計として明確に劣るためだと理解している
- Amazon Kendraは、誤答側の選択肢である可能性が高い。エンタープライズ検索のサービスであって、Bedrock Knowledge BasesでRAG（Retrieval-Augmented Generation）を組む構成が用意されている以上、生成AIアプリケーションの検索層としては選ばれにくい位置にある
- ファインチューニングも、誤答側である可能性が高い。RAGやプロンプトエンジニアリングで満たせる要件に対して、過剰な手段として置かれることが多い。データ準備の重さと運用コストが、要件に見合わない形で設問に埋め込まれている
- 固定長チャンキング（fixed-size chunking）は、常に品質劣化の原因側として扱われていた。意味の切れ目を無視して機械的に区切るため、検索の精度が落ちる側の選択肢になる
- 最も多く登場したサービスはAWS Step Functionsである。生成AIのアプリケーションでも、複数ステップのオーケストレーションや人間の承認を挟むワークフローの受け皿として顔を出す

これらを暗記のリストとして使うでなく、なぜその選択肢が誤答側に置かれるのかを言語化しておくことに意味があります。
初見の設問でも同じ判断ができるようになります。

## 試験当日とスコア

会場はテストセンターです。試験時間は180分ですが、実際にかかったのは見直しと終了後アンケートを含めて60分程度でした。分からない問題を粘っても答えが出るわけではないので、決めたら次に進むという解き方をしています。

体感の内訳を正直に書きます。模擬問題で身に付けた知識をそのまま応用できたのが約4割。自分の知識も使って論理的に導き出せたが確信は持てなかったのが約2割。残る約4割は、ほぼ勘です。

結果は合格、スコアは779点でした。合格ラインの750点から29点差です。4割を勘で答えたという体感と、この点差は整合していると思います。

## まとめ

8月3日から受験日までの3週間、集中して取り組んだように見えるかもしれませんが、実際には大半の時間が
[スプラトゥーン レイダース](https://www.nintendo.com/jp/games/switch2/aadla/index.html)
の無限食堂に溶けていました。勉強そのものに充てたのは、体感で20時間程度です。

試験対策の要点をまとめると、次の5点です。

- 割引バウチャー特典は必ずチェック
- AWSの基本的な知識(AWS Certified Solutions Architect – Associateレベル)は前提として必要
- 知識の整理にはLLMを活用
- 模擬試験で知識を整理し、試験形式に馴れておく
- 上位3コンテンツ分野にフォーカスして学習

AWSを離れたたった2年の期間で生成AIを活用したシステムの典型的なアーキテクチャーがここまで整理され、クラウドプラットフォームではそれを支えるサービスラインナップがここまで充実し具現化していることが、個人的には驚きでした。
AWS自身が、生成AIを活用したアーキテクチャーのベストプラクティスを説明するものとして
"[AWS Well-Architected Generative AI Lens](https://docs.aws.amazon.com/ja_jp/wellarchitected/latest/generative-ai-lens/generative-ai-lens.html)"と言うドキュメントを公開しています。試験には必須ではありませんが、現役の方はぜひ目を通しましょう。

生成AIをどうやってシステムに組み込むのかと悩んでいた時代は過去のものですね。
