# codedchords.dev/ask/ — 構想ドキュメント

## プロジェクト概要

codedchords.dev のメインブログとは独立したインタラクティブなQ&Aページを構築する。訪問者がテキストで質問を入力すると、ブログ著者（Toshiyuki）のペルソナで回答を生成して返す。

回答の生成には Cloudflare Workers AI を使用し、ブログ記事群をナレッジベースとして活用する。ブログに書いてある話題はもちろん、書いていない話題についても、キャラクタ設定とブログ記事から推測される人物像に基づいて「この人ならこう答えるだろう」という回答を生成する。

## 背景と動機

- Cloudflare Workers AI を実践的に使ってみたい
- codedchords.dev に独自性のあるインタラクティブコンテンツを追加したい
- 構築過程そのものがブログ記事のネタになる
- Cloudflare のスタック（Workers AI, Vectorize, Workers, Pages）をフルに活用する実践例を作りたい

## ユースケース

訪問者が `/ask/` ページにアクセスし、テキストで自由に質問する。

質問の例:

- 「Beatlesの曲をカバーするときに、マスタリングで一番気をつけていることは？」（ブログに書いてある話題）
- 「カリフォルニア州についてどう思う？」（ブログに書いていない話題）
- 「最近の日本のIT業界についてどう思う？」（専門分野に関する話題）
- 「おすすめのギターを一本だけ選ぶとしたら？」（雑談）

回答はテキストで返す。回答に関連するブログ記事がある場合は、その記事へのリンクも添える。

## ペルソナ設定

回答は筆者の人物像に基づくキャラクタ設定で生成する。
具体的なプロフィール、口調、スタンス等の詳細は秘匿情報として
リポジトリ外（`.persona`、Cloudflare Secrets）で管理する。

## ナレッジベース

codedchords.dev のブログ記事（Zola の content ディレクトリにある Markdown ファイル群）をナレッジとして使用する。

記事には以下のような話題が含まれる:

- UAD/UADx プラグインを使った Beatles カバー曲のマスタリング手法
- ギター録音機材とシグナルチェインの構成
- AI アドプション戦略（Palantir「AI haves/have-nots」、千葉銀行の事例等）
- AWS ProServe の変革
- 日本企業の SaaS ガバナンス
- Beatles の録音史・ミュージコロジー

## コスト方針

- Workers AI の無料枠（10,000 Neurons/日）を基本とする
- 無料枠を超過した場合は Workers Paid プラン（月 $5）で $0.011/1,000 Neurons の従量課金
- LLM の回答長を制限（max_tokens）してコストを抑制する
- 回答のキャッシュ（KV）で同一・類似の質問に対する重複推論を回避することも検討

## 運用方針

ナレッジベースの更新は自動化しない。週に1回程度、メインブログのリポジトリから Markdown ファイルを `codedchords-ai` リポジトリにコピーし、push する。push をトリガーに GitHub Actions が走り、差分のある記事のみを処理（チャンク分割 → embedding 生成 → Vectorize に格納）する。

差分検出は、リポジトリ内にマニフェストファイル（JSON: slug → MD5 ハッシュのマッピング）を持ち、前回処理時のハッシュと比較して変更のあったファイルのみ処理する。

## メインブログとの関係

- メインブログ（codedchords.dev）の Zola ビルドパイプラインには一切変更を加えない
- tabi テーマのナビゲーションメニューに `/ask/` へのリンクを1行追加するのみ
- `/ask/` のホスティングは Workers Route または Cloudflare Pages の別プロジェクトで行う
